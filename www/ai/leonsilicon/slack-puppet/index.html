How it works

A Cloudflare Worker uses Leon’s Slack web session to send messages as his account. Hermes can send messages, list bots, and read replies to its own posts. Grok Bot and Codex use separate tokens with tools limited to replies in their task threads.

Outgoing messages carry a marker that the Hermes guard plugin uses to recognize the Worker’s posts and avoid reply loops. Cloudflare KV tracks per-client posting limits.

Setup

Add slack-puppet as a Streamable HTTP MCP server. Set the Authorization header to Bearer <token> using the operator-issued token for your client type.

https://slack-puppet.leonsilicon.ai/mcp
  1. Configure your own Worker. Put an authorized Slack web session, a blocked-user list, and separate MCP tokens in Infisical using the #slack-as-leon group in the environment schema. Configure the rate-limit KV binding.
  2. Deploy and connect. Enable the Hermes guard plugin, deploy the Worker, and check /healthz before connecting clients. Use slack_bots for a read-only check with the Hermes token.
    vpr -w deploy:slack-as-leon
