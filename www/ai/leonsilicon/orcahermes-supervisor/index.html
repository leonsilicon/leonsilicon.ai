Orca supervisor

Orca’s built-in supervisor runs the headless runtime and starts a replacement when it fails.

Runtime recovery

orca serve --supervise runs in the foreground under the platform service manager. Orca delays repeated starts and stops retrying after too many failures. A replacement runtime can reconnect to the terminal daemon if the daemon survived the failure.

Verification

In the isolated Hermes audit, killing the runtime triggered a restart while the same terminal daemon and heartbeat process stayed alive. Killing the supervisor left its runtime running. In a separate Linux test, s6 replaced the killed supervisor after stopping the abandoned runtime. Orca reattached to the same terminal daemon and live workload. Recovery under the Nous-hosted service manager still requires verification.
