Orca supervisor

Orca’s built-in supervisor runs the headless runtime and starts a replacement when it fails.

Runtime recovery

orca serve --supervise runs in the foreground under the platform service manager. Orca delays repeated starts and stops retrying after too many failures. A replacement runtime can reconnect to the terminal daemon if the daemon survived the failure.

Verification

On Nous, killing the runtime triggered a restart. The service log recorded that Orca preserved the running terminal daemon and that the replacement runtime reached ready state. In a separate Linux test, s6 replaced a killed supervisor after stopping its abandoned runtime, and Orca reattached to the same terminal workload. Hosted terminal readback across both failures requires further testing.
